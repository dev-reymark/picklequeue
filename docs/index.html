Venue-First Operations Architecture

PICKLEQUEUE is architected specifically around the physical layout of sports facilities. Rather than cramming controls into a dense administrative table, the screen is balanced into 3 distinct functional zones designed for tablet visibility across the court.

Courts Overview (70%)

Dominates the visual space with high-contrast court cards, live timers, team ratings, and quick +2m/+5m tiebreak extensions.

Queue Sidebar (30%)

Organized FIFO rotation staging upcoming 4-player matches with 1-click court assignment, team balance badges, and group reordering.

Docked Waiting Pool

Bottom tray with checkboxes, quick player registration, status filters (waiting, resting, inactive), and 1-click Auto-Balance (4).

Drift-Free Timers

Uses absolute epoch timestamps (endsAt - Date.now()) so timers never desync when switching browser tabs or sleeping.

Procedural Audio Suite

100% synthesized audio via Web Audio API. Zero external MP3 downloads required. Includes Minimal venue profile to eliminate noisy button clicks.

Intelligent 2v2 Doubles

Evaluates 3 team permutations to minimize skill differential and computes exact match quality percentage for balanced games.

Zero Emojis Standard

Strict professional aesthetic. Replaces playful emojis with sleek semantic color badges and high-contrast typography.

Post-Match Rotation

Conclude matches with 1 click: Return to Pool, Requeue group intact, Mark as Resting (break), or Check Out inactive.

JSON Session Backup

Exports complete session state (players, courts, queue, settings) into JSON backups that can be restored across devices instantly.

Drift-Free Countdown Engine Implementation

Standard setInterval(() => count--, 1000) timers lose seconds over time because modern mobile and laptop browsers throttle background tabs. PICKLEQUEUE calculates countdown time using absolute timestamp math: 

// 1. On Match Start (Saved to Court State):
const startedAt = Date.now();
const endsAt = startedAt + (durationMinutes * 60 * 1000);

// 2. Real-Time Tick (Hook: useGameTimer):
const now = Date.now();
const remainingSeconds = Math.max(0, Math.floor((endsAt - now) / 1000));
const isOvertime = now > endsAt;
const overtimeSeconds = isOvertime ? Math.floor((now - endsAt) / 1000) : 0;

// 3. Milestone Alert Flags (Stored in persistent useRef):
if (remainingSeconds <= 120 && !alertsRef.current.warning2m) {
  alertsRef.current.warning2m = true;
  playSound('warning-2m'); // Triggers strictly once
}
if (remainingSeconds === 0 && !alertsRef.current.timeUp) {
  alertsRef.current.timeUp = true;
  playSound('time-up');   // Game finish buzzer
}

Player Lifecycle Transitions

Every player in PICKLEQUEUE moves through five strictly defined operational states:

WAITING Available for queue grouping & matchmaking
QUEUED Staged on an upcoming queue card
PLAYING Active on a court with running timer
RESTING Taking a break; excluded from auto-balance
INACTIVE Checked out while preserving session log

Contributing Guidelines

Standards and guidelines for developing and contributing to PICKLEQUEUE.

Core Engineering Rules

  • Strictly Zero Emojis: Never use emojis in UI components, badges, or feedback messages. Use semantic color dots or clean Lucide icons.
  • Drift-Free Timers: Always calculate remaining time from endsAt - Date.now(). Never rely on accumulated intervals.
  • Component-Driven UI: Add shared primitives under src/components/ui/ and reuse them consistently.
  • High-Contrast Readability: Timers and team slots must remain clearly legible from several meters away on court tablets.
